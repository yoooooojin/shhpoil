# 에이전트 실행 로그

쉿스포가 실제 Zoro-1 판단 엔진과 함께 동작한 기록입니다. 시나리오마다 사람이 읽는 Markdown 파일과 전체 데이터가 담긴 JSON 파일이 하나씩 있습니다.

| 시나리오 | 보여 주는 것 |
| --- | --- |
| `1_3화까지_판정` | **관찰** 화면의 댓글·추천 영상 모음 → **판단** Zoro-1이 20개씩 판정 → **라우팅** 애매한 글은 Zoro가 더 볼 단서(답글·영상 설명·타임스탬프)를 골라 요청하고 에이전트가 모아 다시 판정 → **행동** 가림/그대로, 안 본 회차 영상은 일시정지하고 경고 |
| `2_엔진끊김_자동복구` | 판단 엔진 연결이 끊기면 키워드 방식으로 대신 가리고(작품 이름 제외), 엔진이 살아나면 5초 안에 대신 처리했던 글을 다시 판정 |
| `3_스포신고_기억장학습` | "스포 아님"으로 글 종류별 기준 조정, "스포였어요"로 그 사건을 스포 기억장에 추가하고 화면 전체 다시 판정 → 다른 영상의 비슷한 글도 가려짐 |

## 로그 읽는 법

- **단계:** 관찰 · 판단 · 라우팅 · 행동 · 학습 · 오류 · 복구
- **확률 / 반영:** Zoro-1이 준 스포 확률과, 이미 본 회차 내용이라 낮춰서(×0.1) 반영한 값
- **기준:** 꼼꼼함 설정과 사용자 반응으로 학습한 보정값을 합친 가림 기준
- **↳ 줄:** Zoro-1이 글마다 돌려준 판정 (종류, 확률, 기억장에서 찾은 사건과 회차, 작성 시점)
- 글은 ID로만 남겼습니다. 댓글 원문과 닉네임은 레포에 올리지 않습니다.

## 다시 기록하는 법

시나리오가 매번 같게 재현되도록 시연 페이지(`demo-page/index.html`, 유튜브 댓글 구조를 본뜬 예시 페이지)에서 실제 Zoro-1 엔진에 연결해 기록했습니다.

1. 레포 폴더에서 `python -m http.server 8000` → 브라우저에서 `http://localhost:8000/demo-page/index.html`
2. 확장 팝업 고급 설정의 판단 엔진 주소를 Zoro-1 서버로 맞춤
3. 팝업 **에이전트 실행 로그**에서 기록을 켜고, 시나리오 이름을 쓰고 **새로 시작**
4. 시나리오대로 사용한 뒤 **Markdown**과 **JSON**을 내려받아 이 폴더에 넣음
