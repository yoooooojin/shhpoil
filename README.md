## 문제

- 예능·드라마를 아직 다 못 봤는데 유튜브 클립이나 리뷰 영상 댓글을 열면 결과가 그대로 보입니다. 흑백요리사2 방영 당시에도 스포일러 때문에 결과를 예측하는 재미가 줄었다는 반응이 나왔습니다.
- 댓글만이 아닙니다. 영상 옆 **추천 목록과 쇼츠 제목**("○○ 우승 소감 풀버전")이 먼저 스포를 터뜨립니다.
- 기존 국내 스포일러 차단 확장(유튜브용 포함)은 **키워드 방식**입니다.
  - 출연자 이름만 나와도 다 가려서 **"셰프님 말투 웃김"** 같은 평범한 감상까지 사라집니다.
  - 반대로 **"그 셰프 결국 그 장면에서..."**처럼 돌려 말한 스포는 놓칩니다.
  - **진짜 결과**와 **루머**("○○ 우승설 돌던데")를 구분하지 못합니다. 둘 다 같은 단어를 쓰니까요.
  - 내가 **이미 본 회차**의 이야기인지 모릅니다. 3화 탈락자 얘기는 3화까지 본 사람에겐 스포가 아닌데도 가려집니다.

## 해결

쉿스포는 글마다 **판단**합니다.

| 판단     | 내용                                                        | 담당                                      |
| -------- | ----------------------------------------------------------- | ----------------------------------------- |
| **시점** | 이 글은 몇 화 공개 후에 쓰였나?                             | 작성 시각(YouTube API) + 공개 일정 (코드) |
| **성격** | 결과 공개 / 유출 주장 / 루머·추측 / 감상 / 무관             | Zoro 결정 헤드                            |
| **사건** | 커뮤니티에서 쌓은 스포 기억장 중 어떤 사건(몇 화)을 말하나? | Zoro 결정 헤드 + 기억장                   |

→ **내가 본 회차보다 뒤의 사건을 드러내는 글만** 가립니다.

**어디서:** 유튜브 영상 댓글·답글 · 추천 영상 목록·홈·검색의 영상 제목 · 쇼츠 카드와 쇼츠 댓글 · **지금 보는 영상 자체** (재생 전 경고) · 넷플릭스(본 회차 확인)

## 왜 Zoro-1인가

| Zoro-1 특성                                          | 쉿스포에서                                          |
| ---------------------------------------------------- | --------------------------------------------------- |
| 정해진 선택지 안에서 판단 (one prefill per decision) | 글 종류와 사건을 목록에서 고르므로 엉뚱한 답이 없음 |
| 보정된 확률                                          | 사용자 **민감도 슬라이더**가 그대로 확률 기준이 됨  |
| 빠름                                                 | 스크롤할 때마다 들어오는 글 수십 개를 바로 판정     |
| 선택지 확률을 바로 줌 (decide head)                  | 애매한 글은 단서를 더 넣어 **바로 다시 판정** (글 1개 0.5초 안쪽) |
| 한국어                                               | 한국 커뮤니티 말투, 돌려 말하기 이해                |

## 에이전트 구조

```
 [관찰] 화면의 글 수집 (보이는 것 먼저)          ─┐
    ↓  댓글 · 답글(+원댓글) · 추천 영상 · 쇼츠    │
 [판단] 시점 · 성격 · 사건 → 스포 확률     ─ 판단 엔진 (Zoro-1)
    ↓                                            │
 [행동] 가림 / 흐림+의심 / 단서 모아 재판정 / 그대로 │ 행동·학습 에이전트
    ↓  엔진이 죽으면 키워드로 대신 가리고 자동 복귀 │
 [학습] 사용자 반응 → 글 종류별 기준 조정        │
        "스포였음" 신고 → 기억장에 사건 추가      ─┘
        → 화면 전체 재판정 (돌려 말한 글까지)
```

- **사용자에게서 배움:** "스포 아님 / 스포였음" 버튼으로 글 종류별 기준이 사람마다 달라집니다. 직접 판정한 글은 **누른 회차를 기준으로** 기억합니다. 3화까지 보고 "스포 아님"을 누른 글은 3화 이상에서만 계속 보이고, 1~2화로 돌리면 다시 판단합니다.
- **커뮤니티에서 배움:** "스포였음" 신고가 들어오면 판단 엔진이 그 글의 사건과 회차를 뽑아 **스포 기억장**에 추가하고, 화면의 글을 전부 다시 판단합니다. 다른 영상에서 키워드 없이 돌려 말한 글까지 같이 가려집니다.
- **문맥 활용:** 답글은 원댓글과 함께, 쇼츠 댓글은 쇼츠 제목과 함께 판단합니다.
- **스스로 버팀:** 판단 엔진이 응답하지 않으면 키워드 방식으로 대신 가리고(작품 이름 같은 단어는 빼고), 5초마다 엔진을 확인해 살아나면 자동으로 돌아옵니다.
- **먼저 말 걸기:** 아직 안 본 회차 내용을 "스포 아님"으로 누르면 "혹시 13화까지 보셨나요?"라고 진도를 추측해 묻고, 방영 중인 작품은 새 회차가 공개되면 "보셨나요?"라고 먼저 물어봅니다.
- **넷플릭스 시청 확인:** 넷플릭스에서 같은 작품의 회차를 90% 넘게 보면 "3화를 다 보셨네요! 본 회차를 3화로 바꿀까요?"라고 물어요. 넷플릭스 화면엔 시즌 정보가 없어서 바로 바꾸지 않고 꼭 확인을 받아요. 지금 설정보다 앞선 회차일 때만 묻습니다.

### 화면에서 보이는 것

유튜브 글꼴·크기·밝은/어두운 테마에 맞춰 화면에 섞여 보이게 만들었어요.

- **가린 글:** 본문을 접고 "🤫 스포라서 가렸어요 · 13화 내용 · 결과 공개 87%" 한 줄과 **보기 · 스포 아님 · 왜?** 버튼. 의심되는 글은 흐리게. 가린 글의 이유에는 사건 내용을 쓰지 않습니다 (이유가 스포가 되지 않게).
- **보이는 글:** 평소엔 아무것도 없고, 마우스를 올리면 오른쪽 위에 "이미 본 3화 내용이라 그대로 뒀어요 · 스포였어요 · 왜?"
- **지금 보는 영상 경고:** 영상 제목이 본 회차 뒤 내용이면 재생 전에 플레이어를 덮고 "계속 볼까요?"를 물어요. 넘긴 영상은 상태창에서 "다시 가리기" 가능.
- **상태창 (오른쪽 아래):** 평소엔 `🤫 3` 알약, 누르면 펼쳐짐 · 끌어서 옮기기 · ＋1화 · 판정 모드 · 가림/의심 개수 · 응답 시간 · 지금 영상 판단 결과 · 엔진 연결 상태
- **툴바 아이콘:** 이 페이지에서 가린 개수를 숫자로 표시.
- **🧠 스포 기억장 패널:** 엔진이 짚은 사건을 회차별로 모아 보여 줍니다. 아직 안 본 회차의 사건은 `🔒`로 잠기고, 본 회차를 올리면 풀립니다. 새로 추가된 사건은 `🆕`.
- **⚖ 키워드 방식과 비교 보기 (팝업에서 켜기):** 쉿스포와 키워드 방식의 판단이 갈린 글에 `키워드였다면 놓침` / `키워드였다면 괜히 가림` 꼬리표를 달고, 상태창에 `스포 N개 더 잡음 · 수다 M개 덜 가림`을 보여 줍니다.
- **팝업:** 켜기/끄기 · 작품 · 본 회차(−/＋) · 꼼꼼함 3단계가 위에, 엔진 주소·속도·API 키·학습 기록·**잘못 판단한 글 CSV 내려받기**는 "고급 설정" 안에.
- **첫 설치 안내:** 설치하면 작품 → 본 회차 → 꼼꼼함 3단계 안내가 열려요.


## 실행

### 1. 판단 엔진 켜기

**개발용 (Zoro 없이)**

```bash
python mock-server/server.py          # http://localhost:8787  (macOS/Linux: python3)
```

가짜 엔진은 단어 규칙으로 흉내만 냅니다. `/judge`, `/report`, `/health`와 시연 페이지(`/demo/`)를 제공합니다.

**실제 (Zoro-1, Brev GPU 서버)**

```bash
# 서버 (Brev 인스턴스, tmux에서) · CUDA 13 이상 필요 (nvidia-smi로 확인)
python3 engine/learn_from_articles.py --seed engine/config/memory.흑백요리사2.csv   # 스포 기억장
nohup python3 engine/server.py > ~/engine.log 2>&1 &                                # 판단 엔진 :8787
cd ../trida-stack/inference/zoro-1 && python serve.py --mode decide --port 30001   # Zoro-1 :30001
```

처음부터 설치하는 순서와 엔진 옵션은 [`engine/README.md`](engine/README.md).

내 노트북에서 서버에 붙기 (Windows는 WSL의 Ubuntu에서):

```bash
brev login                                       # 팀 조직 선택
brev port-forward unfair-indigo-mastodon-sshpoil-cu13 -p 8790:8787
```

확장 팝업의 판단 엔진 주소를 `http://localhost:8790`으로 바꾸면 됩니다. 로컬 포트를 8790으로 두면 가짜 엔진(8787)과 동시에 켜 둘 수 있습니다.

- Windows에서 `brev`는 WSL 안에만 설치됩니다. `wsl`이 다른 리눅스(예: Docker Desktop)로 들어가면 `wsl -d Ubuntu-22.04`로 들어가세요.
- Brev 웹의 HTTP 주소는 브라우저 로그인이 필요해서 확장이 쓸 수 없습니다. port-forward를 쓰세요.

### 2. 확장 설치

1. 크롬에서 `chrome://extensions` 열기
2. 오른쪽 위 **개발자 모드** 켜기
3. **압축해제된 확장 프로그램을 로드합니다** → `extension/` 폴더 선택
4. 코드를 바꾼 뒤에는 쉿스포 카드의 **새로고침(↻)** 을 누르고, 카드의 버전 번호와 화면 오른쪽 아래 상태창의 버전이 바뀌었는지 확인합니다. (수정할 때마다 `manifest.json`의 `version`을 올려 주세요.)

### 3. 써 보기 (시연 페이지)

1. http://localhost:8787/demo/ 열기 (유튜브 영상 페이지처럼 생긴 가상 페이지)
2. 확장 아이콘 → 판단 엔진 주소 확인 (`연결됨`이 뜨면 OK)
3. **본 회차**를 3 → 7 → 13으로 바꾸며 가려지는 댓글과 추천 영상 제목이 달라지는 것 확인
4. 상태창의 **🧠 스포 기억장**을 눌러 펼치고, 회차를 올리면 `🔒` 사건이 풀리는 것 확인
5. **신고:** 1번 영상의 "순댓국 나오는 순간 눈물 났다"에 **스포였음** → 2번 영상으로 가면 "그 순댓국 하나로 다 정리됐지 뭐"도 가려짐
6. **비교:** 팝업에서 **키워드 방식과 비교 보기**를 켜거나, **판정 모드 ↔ 키워드 모드**를 바꿔 두 방식 비교
7. **오류 대응:** 판단 엔진 터미널에서 `Ctrl+C` → 회차 한 번 바꾸기 → "⚠ 판단 엔진 연결 끊김 → 키워드로 대체 중" → 엔진 다시 켜기 → 5초 안에 자동 복구

### 4. 실제 유튜브에서 쓰기

1. 유튜브 영상 페이지를 열고 아래로 스크롤해 댓글을 불러오기. 추천 목록·홈·검색의 영상 제목과 쇼츠 카드, 쇼츠 댓글 창도 같이 판단합니다.
2. (선택) 확장 팝업에 **YouTube API 키**를 넣으면 댓글과 영상의 정확한 작성 시각으로 판단합니다.
   - 키가 없으면 "10개월 전" 같은 표시로 대략 계산합니다. 방영 중인 작품은 이것으로도 충분하지만, 끝난 작품은 키가 있어야 회차 판단이 정확합니다.
   - 키 발급: Google Cloud Console → 새 프로젝트 → **YouTube Data API v3** 사용 설정 → 사용자 인증 정보 → **API 키** 만들기 → API 제한을 YouTube Data API v3로 설정 (무료, 댓글·영상 50개당 할당량 1)
   - **API 키는 레포에 올리지 마세요.** 팝업에 입력하면 브라우저에만 저장됩니다. 화면 캡처를 공유할 때도 키가 보이지 않게 주의하세요.
3. 시연할 땐 영상 주소 뒤에 `&lc=댓글ID`를 붙이면 그 댓글이 맨 위에 고정됩니다 (댓글 ID는 수집 CSV의 `comment_id`).
4. 유튜브가 화면 구조를 바꿔 안 잡히면 `extension/sites.js`의 선택자를 개발자 도구(F12)로 확인해 고칩니다. 댓글은 `ytd-comment-view-model`, 영상 카드는 `yt-lockup-view-model` · `ytm-shorts-lockup-view-model-v2` 등입니다.

### 5. 웹 체험판 (GitHub Pages)

`demo-page/try.html`은 크롬 확장 없이도 쉿스포를 써 볼 수 있는 페이지예요. 확장 코드(`extension/content.js`, `sites.js`, `content.css`)를 **그대로** 불러오고, 크롬 확장 기능만 대신해 줍니다(`demo-page/shim.js`).

- 설정은 위쪽 막대(회차·꼼꼼함·판정 방식·비교·영상 경고)에서 바꾸고, 이 브라우저에만 저장돼요.
- 판단은 브라우저 안의 간이 엔진(`demo-page/engine.js`: 단어 규칙 + 방영 일정 + 스포 기억장 `memory.js`)이 해요. 체험판 설정에 `serverUrl`이 있으면 진짜 판단 엔진으로 보내고, 실패하면 간이 엔진으로 돌아와요.
- 확장 코드를 고치면 체험판도 같이 바뀌어요.

배포: 레포 **Settings → Pages → Branch: `main` / `(root)`** → 1~2분 뒤 `https://yoooooojin.github.io/shhpoil/`에서 열려요. 로컬에선 레포 폴더에서 `python -m http.server 8600` 후 http://localhost:8600/ (확장이 설치된 크롬이면 확장과 겹쳐 두 번 동작할 수 있으니 다른 브라우저나 시크릿 창에서).

```powershell
python tools/collect_comments.py 영상주소_또는_ID 다른영상 --max 50
```

- `written_after_episode`(몇 화 공개 후 작성)는 공개 일정으로 자동 계산되고, `event_episode` · `type` · `note`는 사람이 채우는 라벨 칸입니다.

## API

판단 엔진(`engine/`, `mock-server/`)은 아래 형식을 지킵니다. 바꿀 땐 팀원과 먼저 상의하세요.

### `POST /judge` — 판정

```http
POST /judge                 # 다시 판정: /judge?reason=true
Content-Type: application/json

{
  "show": "흑백요리사2",
  "watched_episode": 3,
  "comments": [
    { "id": "c1", "text": "...", "posted_at": "2026-01-13T19:25:00+09:00", "context": "영상 제목" }
  ]
}
```

```json
{
  "results": [
    {
      "id": "c1",
      "p_spoiler": 0.82,
      "type": "결과 공개",
      "written_after_episode": 13,
      "matched_event": { "text": "최강록 최종 우승", "episode": 13, "p": 0.95 },
      "reasoned": false,
      "memory_update": null
    }
  ]
}
```

### `POST /report` — 스포 신고 → 기억장 추가

```http
POST /report
Content-Type: application/json

{
  "show": "흑백요리사2",
  "watched_episode": 3,
  "comment": { "id": "c15", "text": "...", "posted_at": "2026-01-15T10:20:00+09:00", "context": "영상 제목" }
}
```

```json
{
  "memory_update": {
    "added": true,
    "event": { "id": "e26", "text": "요리괴물 결승 메뉴 순댓국", "episode": 13 }
  }
}
```

- `added`: 새 사건을 추가했으면 `true`, 이미 있던 사건이면 `false` (`event`에는 기존 사건)
- 확장은 `added: true`를 받으면 기억장 패널에 `🆕`로 표시하고 화면 전체를 다시 판단합니다.
- `/report`가 없는 엔진이어도 확장은 깨지지 않습니다 (신고만 조용히 실패).

### `GET /health`

```http
GET /health   →   { "ok": true, "engine": "zoro-1" }
```

- `type`: `결과 공개` · `유출 주장` · `루머·추측` · `감상·출연자 이야기` · `무관`
- CORS 허용 필요 (`Access-Control-Allow-Origin: *`)
- 응답에 다른 칸(`type_probs`, `reason_brief` 등)이 더 있어도 확장은 무시합니다.

### 요청 필드

| 필드              | 뜻                                                                                       |
| ----------------- | ---------------------------------------------------------------------------------------- |
| `show`            | 작품명 (팝업에서 설정)                                                                   |
| `watched_episode` | 사용자가 본 회차                                                                         |
| `comments[].id`   | 글 고유 번호. 유튜브 댓글은 댓글 ID, 영상 카드는 `v:영상ID`                              |
| `posted_at`       | 작성(업로드) 시각 (ISO). API 키가 없으면 "10개월 전" 표시로 추정한 대략값. 모르면 `null` |
| `context`         | 글이 놓인 맥락 (아래)                                                                    |

`context` 형식:

| 글                  | `context`                                      |
| ------------------- | ---------------------------------------------- |
| 영상 댓글           | `영상 제목`                                    |
| 답글                | `영상 제목\n원댓글: 원댓글 내용` (최대 300자)  |
| 쇼츠 댓글           | 쇼츠 제목 (탭 제목에서)                        |
| 추천 영상·쇼츠 카드 | `[추천 영상 제목] 채널명` → `text`가 영상 제목 |

### 응답 필드

| 필드                    | 뜻                                                                | 없을 때                         |
| ----------------------- | ----------------------------------------------------------------- | ------------------------------- |
| `id`                    | 요청에서 받은 값을 **그대로** 돌려줌                              | — (필수)                        |
| `p_spoiler`             | 스포일러일 확률 0~1 (Trida 판단 헤드 출력)                        | — (필수)                        |
| `type`                  | 글 종류 5가지 중 하나                                             | — (필수)                        |
| `written_after_episode` | 작성 시각 기준, 몇 화까지 공개된 뒤에 쓴 글인지                   | `null` → 확장이 보수적으로 가림 |
| `matched_event`         | 스포 기억장에서 맞는 사건 (`p` ≥ 0.5일 때 회차 판단에 사용)       | `null`                          |
| `reasoned`              | Zoro가 추론 결과까지 써서 판단했으면 `true` (지금 엔진은 재판정에서 추론을 쓰지 않아 늘 `false`) | `false`                         |
| `need_context`          | 애매한 글(0.3~0.75)에서 Zoro가 더 보고 싶은 단서, 최대 2개 (`parent` `replies` `description` `timestamp`) | `null`                          |
| `used_clues`            | 단서를 받아 다시 판단했을 때 실제로 쓴 단서                        | `null`                          |
| `memory_update`         | 이 글을 판단하다 기억장에 사건을 추가했으면 `/report`와 같은 모양 | `null`                          |

### 약속

- **한 번에 보내는 양**: 글 최대 20개. 20개를 2~3초 안에 응답하는 게 목표입니다.
- **응답 시간 제한**: 일반 판정 **10초**, 다시 판정·신고 **20초**. 넘기면 확장이 실패로 보고 키워드 방식으로 대신 가립니다. 현장에서 Zoro 속도를 보고 `extension/background.js`의 `JUDGE_TIMEOUT_MS`, `REASON_TIMEOUT_MS`를 조정합니다.
- **다시 판정** (`?reason=true`): 확률이 기준선 근처라 애매한 글만 1개씩, 글당 **한 번만** 다시 묻습니다. 처음엔 Zoro 추론을 썼지만, 추론이 512토큰에서 잘려 버려지면서 글 1개에 7~8초가 걸렸고 주관적 판단엔 추론을 권하지 않는다는 모델 카드에 따라 껐습니다. 지금은 단서를 넣어 판단 헤드로 바로 물어 0.5초 안쪽입니다.
- **단서 더 모으기**: 처음 보낼 때 글마다 `available_clues`(확장이 모을 수 있는 단서)를 붙입니다. 응답에 `need_context`가 있으면 확장이 그 단서(원댓글 전문, 답글 5개, 영상 설명, 타임스탬프가 가리키는 챕터)를 모아 `clues`에 담아 그 글만 `?reason=true`로 다시 보냅니다. 답글·영상 설명은 YouTube API 키가 있을 때만 모읍니다.
- **방영 일정표** (흑백요리사2, 한국 시간 17:00 공개): 12/16 1~3화 · 12/23 4~7화 · 12/30 8~10화 · 1/6 11~12화 · 1/13 13화. `written_after_episode` 계산에 씁니다.

## 행동 규칙

| 조건                           | 행동                                                                   |
| ------------------------------ | ---------------------------------------------------------------------- |
| 사용자가 "스포 아님"을 누른 글 | 누른 회차 **이상**을 보고 있으면 계속 보임, 그보다 앞이면 다시 판단    |
| 사용자가 "스포였음"을 누른 글  | 누른 회차 **이하**를 보고 있으면 계속 가림, 더 봤으면 다시 판단        |
| 이미 본 회차의 내용            | 그대로 둠                                                              |
| 스포 확률 ≥ 기준 + 15%p        | **가림**                                                               |
| 스포 확률 ≥ 기준               | **흐림 + "스포 의심"**                                                 |
| Zoro가 단서 요청 (`need_context`) | 일단 흐리고 **요청한 단서를 모아 다시 판정** (1회, 배지에 🔍)         |
| 기준 ±10%p 안쪽 (애매)         | 일단 흐리고 **다시 판정** (1회)                                        |
| 판단 엔진 연결 실패·시간 초과  | **키워드 방식으로 대체** (작품 이름은 제외), 엔진이 살아나면 자동 복귀 |
| 가린 추천 영상                 | "보기"를 누르기 전엔 클릭해도 열리지 않음                              |
| 지금 보는 영상이 본 회차 뒤 내용 | 일시정지 + 플레이어를 덮고 계속 볼지 물어봄 (회차를 바꾸거나 새로고침하면 다시 물어봄) |

기준 = 민감도 슬라이더 값 + 사용자 반응으로 학습한 글 종류별 보정값(±30%p 한도)

## 평가

유튜브 흑백요리사2 댓글에 라벨을 달고, 같은 댓글로 키워드 방식과 비교했습니다. 꼼꼼함 단계와 규칙은 dev 세트로 정하고, 아래 숫자는 test 세트에서 잰 값입니다.

- **라벨:** 댓글마다 **몇 화 내용을 드러내는지**(`event_episode`, 결과가 없으면 비움)와 글 종류(`type`)를 적습니다. "N화까지 본 사람에게 스포인가"는 `event_episode > N`으로 계산하므로, 한 번 라벨링으로 여러 시청 회차 기준의 채점이 가능합니다.
- **채점 회차 (3·7·10·12화):** 공개일마다 그날까지 공개된 마지막 회차입니다. "방금 나온 회차까지 본 사람"이 제일 흔한 시청자라서 이 네 시점으로 잽니다.
- **AI 초벌 + 사람 검수:** Claude로 초벌 라벨을 달고 김서형이 검수했습니다. 맞은 추측(루머가 사실로 드러난 것)은 스포로 칩니다.
- **기준 맞추기:** 댓글 20개를 사람이 직접 달아 AI 초벌과 비교했습니다. 글 성격, 스포 여부, 회차 모두 95% 일치(20개 중 19개)했고, 어긋난 기준을 정리한 뒤 라벨링했습니다.
- 기억장만 보고 라벨링하지 않습니다. 기억장이 틀리면 정답지도 같이 틀려 점수가 부풀기 때문입니다.

**놓친 스포 % / 잘못 가린 글 %** (낮을수록 좋음, test 세트)

| N화까지 본 사람 (스포 수) | 키워드 방식 | 쉿스포 꼼꼼함 0.4 | 쉿스포 0.5 (기본) | 쉿스포 0.7 |
| ------------------------- | ----------- | ----------------- | ----------------- | ---------- |
| 3화 (87)                  | 51.7 / 15.3 | 44.8 / 11.5       | 41.4 / 15.3       | 31.0 / 24.2 |
| 7화 (78)                  | 46.2 / 14.5 | 43.6 / 6.6        | 38.5 / 9.6        | 33.3 / 18.1 |
| 10화 (60)                 | 30.0 / 13.0 | 55.0 / 1.6        | 45.0 / 3.3        | 31.7 / 6.0  |
| 12화 (44)                 | 18.2 / 15.0 | 100.0 / 0.5       | 100.0 / 0.5       | 84.1 / 0.5  |

- **3·7화:** 기본(0.5)에서 키워드보다 덜 놓치고(52→41%, 46→39%), 잘못 가린 글은 같거나 적습니다.
- **10화:** 잘못 가린 글이 13%에서 3%로 줄지만, 놓친 스포는 키워드가 더 적습니다. 0.7로 올리면 놓침이 키워드와 비슷해지고(32%) 잘못 가림은 6%입니다.
- **12화 (약점):** 거의 다 놓칩니다. 놓친 44개 중 19개는 13화 공개 후 쓴 글인데 12화 사건으로 연결됐습니다. 13화(결승) 반응거리가 기억장에 적었던 탓으로 보고, 기사로 확인한 13화 사건 6개를 기억장에 더했습니다(dev2 12화 놓침 58% → 50%). 이 최종 엔진은 새 test 세트로 따로 재서 추가합니다.
- **기억장의 효과:** 기억장을 끄면 스포의 93~96%를 놓칩니다. 판단력의 핵심은 기억장과 Zoro-1의 사건 연결입니다.
- **확률 보정:** Brier 점수 0.10~0.17 (Zoro 확률이 실제 비율과 대체로 맞음).
- **속도:** 댓글 20개 한 번 판정 약 1.9초, 애매한 글 다시 판정 0.5초 안쪽 (Brev L40S, Zoro-1 decide head). 위 표는 최종 엔진 이전 버전(20개 약 3.3초)으로 잰 값입니다.

> 평가 데이터의 원문 글과 닉네임은 레포에 올리지 않습니다 (`eval/labels.csv`는 댓글 ID와 라벨만).
