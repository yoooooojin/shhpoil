# 🤫 쉿스포 (Shhpoil)

> **내가 본 데까지만 보여주는 스포일러 판정 에이전트**
> Episode-aware spoiler blur for Korean communities, powered by Zoro-1

TRILLION AGENT AI HACKATHON 2026 · Track 1 (Zoro-1 Arena) 출품작 · 팀 Queentillion

---

## 문제

- 예능·드라마를 아직 다 못 봤는데 유튜브 클립이나 리뷰 영상 댓글을 열면 결과가 그대로 보입니다. 흑백요리사2 방영 당시에도 스포일러 때문에 결과를 예측하는 재미가 줄었다는 반응이 나왔습니다.
- 기존 국내 스포일러 차단 확장(유튜브용 포함)은 **키워드 방식**입니다.
  - 출연자 이름만 나와도 다 가려서 **"셰프님 말투 웃김"** 같은 평범한 감상까지 사라집니다.
  - 반대로 **"그 셰프 결국 그 장면에서..."**처럼 돌려 말한 스포는 놓칩니다.
  - **진짜 결과**와 **루머**("○○ 우승설 돌던데")를 구분하지 못합니다. 둘 다 같은 단어를 쓰니까요.
  - 내가 **이미 본 회차**의 이야기인지 모릅니다. 3화 탈락자 얘기는 3화까지 본 사람에겐 스포가 아닌데도 가려집니다.

## 해결

쉿스포는 글마다 **판단**합니다.

| 판단     | 내용                                                        | 담당                                      |
| -------- | ----------------------------------------------------------- | ----------------------------------------- |
| **시점** | 이 글은 몇 화 공개 후에 쓰였나?                             | 작성 시각(YouTube API) + 공개 일정 (코드) |
| **성격** | 결과 공개 / 유출 주장 / 루머·추측 / 감상 / 무관             | Zoro 결정 헤드                            |
| **사건** | 커뮤니티에서 쌓은 스포 기억장 중 어떤 사건(몇 화)을 말하나? | Zoro 결정 헤드 + 기억장                   |

→ **내가 본 회차보다 뒤의 사건을 드러내는 글만** 가립니다.

## 왜 Zoro-1인가

| Zoro-1 특성                                          | 쉿스포에서                                          |
| ---------------------------------------------------- | --------------------------------------------------- |
| 정해진 선택지 안에서 판단 (one prefill per decision) | 글 종류와 사건을 목록에서 고르므로 엉뚱한 답이 없음 |
| 보정된 확률                                          | 사용자 **민감도 슬라이더**가 그대로 확률 기준이 됨  |
| 빠름                                                 | 스크롤할 때마다 들어오는 글 수십 개를 바로 판정     |
| 헷갈릴 때만 추론                                     | 기준 근처의 애매한 글만 **추론 모드로 재판정**      |
| 한국어                                               | 한국 커뮤니티 말투, 돌려 말하기 이해                |

## 에이전트 구조

```
 [관찰] 화면의 글 수집 (보이는 것 먼저)          ─┐
    ↓                                            │ 행동·학습 에이전트
 [판단] 시점 · 성격 · 사건 → 스포 확률     ─ 판단 엔진 (Zoro-1)
    ↓                                            │
 [행동] 가림 / 흐림+의심 / 추론 재판정 / 그대로   │
    ↓                                            │
 [학습] 사용자 반응 → 글 종류별 기준 조정        ─┘
        확실한 스포 → 기억장에 회차별 사건 축적
```

- **사용자에게서 배움:** "스포 아님 / 스포였음" 버튼으로 글 종류별 기준이 사람마다 달라집니다. 직접 판정한 댓글은 회차를 바꾸거나 새로고침해도 그 결정을 유지합니다.
- **커뮤니티에서 배움:** 확실한 스포에서 드러난 사건을 회차와 함께 저장하고, 이후 돌려 말한 글을 그 사건과 비교해 잡습니다. 키워드를 사람이 넣지 않아도 에이전트가 스스로 "스포 사전"을 만듭니다.
- **문맥 활용:** 답글은 원댓글과 함께 판단합니다 ("ㄹㅇ 결국 그분이 가져감"처럼 원댓글을 봐야 뜻을 아는 글).

## 폴더 구조

```
shhpoil/
├── extension/     크롬 확장: 관찰 · 행동 · 학습 에이전트, 화면
├── engine/        판단 엔진: Zoro-1 서빙, 판정, 스포 기억장
├── eval/          평가 스크립트, 키워드 방식 비교군
├── tools/         댓글 수집 스크립트 (라벨링용 CSV 생성)
├── mock-server/   개발용 가짜 판단 엔진 + 시연 페이지 제공
└── demo-page/     유튜브처럼 생긴 시연 페이지 (비상용)
```

## 실행

### 1. 판단 엔진 켜기

**개발용 (Zoro 없이)**

```bash
python mock-server/server.py          # http://localhost:8787  (macOS/Linux: python3)
```

**실제 (Zoro-1)**

```bash
# TODO: engine/ 실행 방법
```

### 2. 확장 설치

1. 크롬에서 `chrome://extensions` 열기
2. 오른쪽 위 **개발자 모드** 켜기
3. **압축해제된 확장 프로그램을 로드합니다** → `extension/` 폴더 선택
4. 코드를 바꾼 뒤에는 쉿스포 카드의 **새로고침(↻)** 을 누르고, 카드의 버전 번호와 화면 오른쪽 아래 상태창의 버전이 바뀌었는지 확인합니다. (수정할 때마다 `manifest.json`의 `version`을 올려 주세요.)

### 3. 써 보기 (시연 페이지)

1. http://localhost:8787/demo/ 열기 (유튜브 영상 페이지처럼 생긴 가상 페이지)
2. 확장 아이콘 → 판단 엔진 주소 확인 (`연결됨`이 뜨면 OK)
3. **본 회차**를 3 → 7 → 13으로 바꾸며 가려지는 댓글이 달라지는 것 확인
4. 오른쪽 **다음 동영상**을 눌러 다른 회차 영상의 댓글 보기
5. **판정 모드 ↔ 키워드 모드**를 바꿔 같은 화면에서 두 방식 비교

### 4. 실제 유튜브에서 쓰기

1. 유튜브 영상 페이지를 열고 아래로 스크롤해 댓글을 불러오기
2. (선택) 확장 팝업에 **YouTube API 키**를 넣으면 댓글의 정확한 작성 시각으로 판단합니다.
   - 키가 없으면 "10개월 전" 같은 표시로 대략 계산합니다. 방영 중인 작품은 이것으로도 충분하지만, 끝난 작품은 키가 있어야 회차 판단이 정확합니다.
   - 키 발급: Google Cloud Console → 새 프로젝트 → **YouTube Data API v3** 사용 설정 → 사용자 인증 정보 → **API 키** 만들기 → API 제한을 YouTube Data API v3로 설정 (무료, 댓글 50개당 할당량 1)
   - **API 키는 레포에 올리지 마세요.** 팝업에 입력하면 브라우저에만 저장됩니다. 화면 캡처를 공유할 때도 키가 보이지 않게 주의하세요.
3. 유튜브가 화면 구조를 바꿔 댓글이 안 잡히면 `extension/sites.js`의 유튜브 선택자를 개발자 도구(F12)로 확인해 고칩니다.

### 5. 평가용 댓글 수집

```powershell
$env:YT_API_KEY="API_키"                  # 키는 환경변수로만 (macOS/Linux: export YT_API_KEY=...)
python tools/collect_comments.py 영상주소_또는_ID 다른영상 --max 50
```

- 결과는 `data/comments_날짜.csv` (엑셀에서 바로 열림). `data/`는 `.gitignore`에 넣어 레포에 올리지 않습니다.
- `written_after_episode`(몇 화 공개 후 작성)는 공개 일정으로 자동 계산되고, `event_episode` · `type` · `note`는 사람이 채우는 라벨 칸입니다.
- 옵션: `--order time` 최신순, `--replies` 답글 포함(스레드당 5개).

## API

판단 엔진(`engine/`, `mock-server/`)은 아래 형식을 지킵니다. 바꿀 땐 팀원과 먼저 상의하세요.

```http
POST /judge                 # 추론 모드: /judge?reason=true
Content-Type: application/json

{
  "show": "흑백요리사2",
  "watched_episode": 3,
  "comments": [
    { "id": "c1", "text": "...", "posted_at": "2026-01-13T19:25:00+09:00", "context": "영상 제목" }
  ]
}
```

```json
{
  "results": [
    {
      "id": "c1",
      "p_spoiler": 0.82,
      "type": "결과 공개",
      "written_after_episode": 13,
      "matched_event": { "text": "최강록 최종 우승", "episode": 13, "p": 0.95 },
      "reasoned": false
    }
  ]
}
```

```http
GET /health   →   { "ok": true, "engine": "zoro-1" }
```

- `type`: `결과 공개` · `유출 주장` · `루머·추측` · `감상·출연자 이야기` · `무관`
- CORS 허용 필요 (`Access-Control-Allow-Origin: *`)

### 요청 필드

| 필드              | 뜻                                                                                                     |
| ----------------- | ------------------------------------------------------------------------------------------------------ |
| `show`            | 작품명 (팝업에서 설정)                                                                                 |
| `watched_episode` | 사용자가 본 회차                                                                                       |
| `comments[].id`   | 댓글 고유 번호 (유튜브 댓글 ID)                                                                        |
| `posted_at`       | 작성 시각 (ISO). API 키가 없으면 "10개월 전" 표시로 추정한 대략값. 모르면 `null`                       |
| `context`         | 영상 제목. 유튜브 **답글**이면 `"영상 제목\n원댓글: 원댓글 내용"`처럼 원댓글이 한 줄 붙음 (최대 300자) |

### 응답 필드

| 필드                    | 뜻                                                          | 없을 때                         |
| ----------------------- | ----------------------------------------------------------- | ------------------------------- |
| `id`                    | 요청에서 받은 값을 **그대로** 돌려줌                        | — (필수)                        |
| `p_spoiler`             | 스포일러일 확률 0~1 (Trida 판단 헤드 출력)                  | — (필수)                        |
| `type`                  | 글 종류 5가지 중 하나                                       | — (필수)                        |
| `written_after_episode` | 작성 시각 기준, 몇 화까지 공개된 뒤에 쓴 글인지             | `null` → 확장이 보수적으로 가림 |
| `matched_event`         | 스포 기억장에서 맞는 사건 (`p` ≥ 0.5일 때 회차 판단에 사용) | `null`                          |
| `reasoned`              | 추론 모드로 판단했으면 `true`                               | `false`                         |

### 약속

- **한 번에 보내는 양**: 댓글 최대 20개. 20개를 2~3초 안에 응답하는 게 목표입니다.
- **응답 시간 제한**: 일반 판정 **10초**, 추론 모드 **20초**. 넘기면 확장이 실패로 보고 댓글을 그대로 보여 줍니다. 현장에서 Zoro 속도를 보고 `extension/background.js`의 `JUDGE_TIMEOUT_MS`, `REASON_TIMEOUT_MS`를 조정합니다.
- **추론 모드** (`?reason=true`): 확률이 기준선 근처라 애매한 댓글만 1개씩, 댓글당 **한 번만** 다시 묻습니다. 더 오래 생각해서 판단하고 응답에 `"reasoned": true`를 넣어 주세요.

## 행동 규칙

| 조건                          | 행동                                                |
| ----------------------------- | --------------------------------------------------- |
| 사용자가 직접 판정한 글       | 그 결정을 그대로 따름 (회차 변경·새로고침에도 유지) |
| 이미 본 회차의 내용           | 그대로 둠                                           |
| 스포 확률 ≥ 기준 + 15%p       | **가림**                                            |
| 스포 확률 ≥ 기준              | **흐림 + "스포 의심"**                              |
| 기준 ±10%p 안쪽 (애매)        | 일단 흐리고 **추론 모드로 재판정** (1회)            |
| 판단 엔진 연결 실패·시간 초과 | 가리지 않음 (화면을 막지 않기)                      |

기준 = 민감도 슬라이더 값 + 사용자 반응으로 학습한 글 종류별 보정값(±30%p 한도)

## 평가

유튜브 흑백요리사2 댓글을 두 사람이 나눠 라벨링하고, 같은 댓글로 키워드 방식과 비교합니다.

- **라벨:** 댓글마다 **몇 화 내용을 드러내는지**(`event_episode`, 결과가 없으면 비움)와 글 종류(`type`)를 적습니다. "N화까지 본 사람에게 스포인가"는 `event_episode > N`으로 계산하므로, 한 번 라벨링으로 여러 시청 회차 기준의 채점이 가능합니다.
- **기준 맞추기:** 시작 전에 같은 댓글 20개를 둘이 따로 달아 보고 기준을 맞춥니다.
- 기억장만 보고 라벨링하지 않습니다. 기억장이 틀리면 정답지도 같이 틀려 점수가 부풀기 때문입니다.
